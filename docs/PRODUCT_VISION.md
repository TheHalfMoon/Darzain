# Yamakan product vision

A local-first creative production workspace connects scripts, characters, brands, reference assets, scenes, shots, model jobs and editable films. Users and agents operate on the same durable project. Differentiation is production control, continuity and inspectable provenance, with qualified source reuse rather than unrelated generation wrappers.

The first useful product launches without GPU, Python, provider keys or cloud compute. Users import media, plan shots, edit timeline/audio/titles, preview/export MP4 and reopen an editable project. Optional AI uses a qualified local worker or user BYOK, explicit upload consent, visible estimates and receipts. Founder-funded default capacity is excluded. Commercial subscriptions/credits remain optional future architecture.

These are coherent views, not eleven empty apps. Share asset/project/job/permission components and command semantics. Do not claim generation from placeholders or camera control from stored intent. Distinguish planned, documented, installed, entitled, hardware-compatible and runtime-qualified features.

Arabic and English application support needs localized strings, RTL/LTR layout, mixed-script text shaping, font packaging, captions, keyboard/accessibility testing and native-language quality assessment. All engineering work products remain English. Claude demonstrated wrong RTL base direction in the current drawtext path. The final plan uses shared ASS/libass with explicit font hashes and native-Arabic goldens; neither shaping availability nor shared engine naming is a typography/voice quality pass.
