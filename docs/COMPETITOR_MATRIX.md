## Measurement rules

Register comparable tasks, consented input hashes, requested control, output format, cost/attempt limit and timeout before testing. Capture every failed attempt, output, model/provider/adapter revision, hardware, seed when meaningful, latency and charged receipt. Use ≥20 diverse tasks per initial category and multiple independent blinded raters; report sample size, uncertainty and inter-rater agreement. This is a pilot, not population-wide proof. Increase sample size or narrow claims if confidence intervals cannot distinguish systems.

For quality/continuity/control, publish paired comparisons and a predeclared improvement criterion (for example lower confidence bound of paired preference >50%, with no material regression in artifact rate/cost). For integrity, publish fault/restore success rates and known durability limits. For agent parity, publish exact command/output hashes and intervention counts. For responsiveness/accessibility, publish hardware, p95 task latency and successful keyboard/native-Arabic completion. No benchmark result exists yet. Do not convert Q source tests into I Yamakan features or P targets into achievements.
